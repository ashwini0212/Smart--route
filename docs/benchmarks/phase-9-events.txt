Reading: the delay is the relay's polling wait, not Kafka. At a 500 ms interval the pipeline takes
p50 474 ms; with the same code at 50 ms it takes p50 59 ms, so almost all of the 474 ms is the wait for
the next relay run. The max column in the 50 ms run (1058 ms; an earlier run of the same measurement
showed 930 ms) is one order in fifty waiting on something else - most likely a consumer poll or a
commit - and it did not appear in the 500 ms runs, where that wait hides inside the polling interval.
